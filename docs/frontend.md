# Фронтенд

`apps/web` — React, Vite и TypeScript.

- Роутинг — React Router (`react-router`), роутер в `src/app/router.tsx`.
- Формы — react-hook-form, проверка — схемами zod через `@hookform/resolvers/zod`.
- Состояние — zustand.
- Запросы — axios.
- UI — компоненты shadcn/ui на Tailwind CSS, уведомления — sonner.

## Структура

Код разложен по слоям Feature-Sliced Design:

```
src/
  app/        точка входа, роутер, глобальные стили
  pages/      страницы
  widgets/    крупные самостоятельные блоки страницы
  features/   действия пользователя: создать, отправить, удалить
  entities/   сущности предметной области: пользователь, доска
  shared/     код без предметной области: ui, api, lib
```

- Слой импортирует только из слоёв ниже себя. Слайсы одного слоя друг друга не импортируют.
- Слайс (`pages/home`, `entities/user`) отдаёт наружу только то, что экспортирует его `index.ts`. Снаружи импортируем `@/entities/user`, а не файлы внутри.
- В `shared` слайсов нет, импортируем по файлу: `@/shared/ui/button`, `@/shared/api/client`.
- Внутри слайса код делится на сегменты: `ui`, `model` (сторы zustand), `api`, `lib`, `config`.
- Из других слоёв импортируем через алиас `@/`, внутри слайса — относительными путями.

Пустые слои держит `.gitkeep`. Когда в слое появится первый слайс, его можно удалить.

## Компоненты shadcn

Компоненты лежат в `src/shared/ui`. Это обычный код в репозитории, его можно править. Добавить новый:

```sh
pnpm --filter @repo/web exec shadcn add dialog
```

Если CLI спрашивает, перезаписать ли существующий файл, отвечаем N. Иначе пропадут правки в нём: например, `sonner.tsx` переделан без `next-themes`.

Тёмной темы пока нет: переменные для неё в `src/app/styles/index.css` есть, переключателя нет.

## Запросы к api

- В dev Vite проксирует `/api` на `http://localhost:3000`, поэтому фронт ходит на свой же адрес и CORS не нужен. Если api запущен на другом порту, поменяй прокси в `vite.config.ts`.
- Запросы отправляем через `api` из `@/shared/api/client`: `api.get('/users')` уйдёт на `/api/users`.
- Схемы и типы запросов и ответов берём из `@repo/contracts`.

## Запуск

`pnpm dev` из корня запускает api и web, фронт открывается на http://localhost:5173. Для api нужен Postgres из Docker, см. README.

Только фронт: `pnpm turbo run dev --filter=@repo/web`. Запросы к api тогда работать не будут.
