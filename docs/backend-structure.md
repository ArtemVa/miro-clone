# Структура бэка

`apps/api` делится на модули по предметным областям, модуль — на три слоя. Образец — `apps/api/src/modules/users`.

## Модуль

```
apps/api/src/modules/users/
  users.router.ts       HTTP: адреса, проверка запроса, статусы ответа
  users.service.ts      логика: правила, перевод в формат контракта, ошибки API
  users.repository.ts   база: запросы через Prisma
  users.test.ts         тесты
```

Слой вызывает только слой под собой: router → service → repository → Prisma. О слоях выше нижний слой ничего не знает.

Слои — функции-фабрики, зависимости передаются аргументами. Классы и DI-контейнер не используем. Слои собираются в `apps/api/src/app.ts`:

```ts
api.use('/users', createUsersRouter(createUsersService(createUsersRepository(db))));
```

Клиент базы приходит снаружи, поэтому в тестах подставляется тестовая база.

## Router

- Проверяет params, query и body схемами из contracts через `validateParams`, `validateQuery` и `validateBody` из `common/validate.ts`.
- Вызывает сервис и отдаёт ответ. Тип ответа — из контракта: `Response<User>`.
- Выбирает статус: 201 при создании, 404, если сервис не нашёл запись.
- Не обращается к репозиторию и базе, бизнес-правил не содержит.
- Не ловит ошибки: Express 5 сам передаёт ошибку из async-ручки в обработчик ошибок.

## Service

- Содержит бизнес-правила.
- Принимает и отдаёт типы из contracts. Строку из базы переводит в формат контракта (`toUser`).
- С базой работает только через репозиторий, Prisma не импортирует.
- Про Express, `req` и `res` не знает.
- Ошибку, которую должен получить клиент, бросает как `HttpError` с кодом из contracts. Ошибки базы переводит в ошибки API: `UniqueViolationError` → 409 `CONFLICT`.

## Repository

- Единственное место в модуле, где есть Prisma.
- Принимает обычные значения или типы из contracts, например параметры списка. Возвращает строки из базы. Тип строки экспортирует сам (`UserRow`), чтобы сервис не брал его из Prisma.
- Пагинацию, сортировку и фильтры делает запросом к базе, как описано в [api-conventions.md](api-conventions.md#на-бэке).
- Нарушение ограничения базы переводит в ошибку из `common/db-errors.ts`. Сейчас там одна ошибка — `UniqueViolationError` для кода Prisma `P2002`.
- Бизнес-правил не содержит.

Кроме репозиториев, Prisma используют только `common/db.ts`, `common/db-errors.ts`, `prisma/seed.ts` и тесты. Импорт Prisma в других файлах `apps/api/src` ESLint считает ошибкой (`no-restricted-imports` в `eslint.config.mjs`).

## Запросы к базе

- Связанные данные берём одним запросом: через `include` или `findMany` с `where: { id: { in: ids } }`. Запрос в цикле по записям (N+1) не пишем.
- Из связанных таблиц берём только нужные поля через `select`.
- Если операция пишет в несколько таблиц, запись идёт в одной транзакции. Внутри транзакции нет запросов к внешним сервисам.

## Общий код

В `apps/api/src/common/` лежит то, что нужно нескольким модулям: клиент базы, ошибки базы, логгер, обработчик ошибок, `HttpError`, проверка запросов. Общие middleware, например проверка доступа, тоже кладём сюда и подключаем в `app.ts` или в роутере. Бизнес-логики модулей в `common` нет.
